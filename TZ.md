# ТЗ: Portfolio Terminal — дашборд инвестиционного портфеля

> Техническое задание для Claude Code. Документ самодостаточный: всё, что нужно для реализации, описано здесь.

> Дата: 2026-11-24.

## 1. Зачем этот проект

Это **проект для портфолио frontend-разработчика**. Его задача — доказать, что автор умеет делать дашборды.

Кто будет смотреть:

- **Рекрутер или HR.** У него ~2 минуты: открыть живую ссылку, покликать, посмотреть, что всё быстро, красиво и не ломается.
- **Тимлид или frontend-разработчик на собеседовании.** Откроет репозиторий: структура, типизация, тесты, качество решений, README.

Поэтому важны впечатление в первые секунды, надёжность демо и чистый код. Точность финансового учёта «как у брокера» не нужна, но расчёты должны быть корректными и проверяемыми: на собеседовании о них могут спросить.

## 2. Критерии успеха

1. Живая ссылка открывается и за пару секунд показывает насыщенный, «живой» дашборд: тикающие цены, графики, таблицы. Регистрация не нужна.
2. Демо **никогда не ломается само**: данных из внешних сервисов нет, ключей API нет.
3. Можно добавить сделку через форму, и портфель сразу пересчитывается на всех страницах.
4. Переключение RU/EN мгновенно меняет все тексты и форматы чисел, валют и дат.
5. Сайт нормально выглядит на телефоне.
6. Репозиторий: строгий TypeScript, понятная структура, тесты на расчёты и форму, CI зелёный, README со скриншотами/GIF и ссылкой на демо.
7. Lighthouse (desktop): Performance ≥ 90, Accessibility ≥ 90.

## 3. Цели, не-цели, анти-цели

**Цели**
- Многостраничный SPA-дашборд инвестиционного портфеля на моковых данных.
- Фейковый API в браузере с задержками, чтобы код честно работал с асинхронностью: загрузка, ошибки, кэш.
- Форма сделок (покупка, продажа, дивиденд, пополнение, вывод) с валидацией и пересчётом портфеля.
- Симуляция цен в реальном времени.
- Тёмный стиль «терминал трейдера».
- i18n RU/EN.

**Не-цели**
- Реальные котировки, реальные брокерские API, импорт отчётов брокера.
- Бэкенд, база данных, авторизация, мультипользовательность.
- Светлая тема (выбран только тёмный стиль).
- Мультивалютность: все суммы в одной базовой валюте USD **[решение]**.
- Налоги, сложные инструменты (опционы, фьючерсы, шорты, маржа).

**Анти-цели (провал, даже если «работает»)**
- Шаблонный вид «админка из коробки»: дефолтный MUI/AntD, стоковые цвета графиков.
- Демо, которое падает, висит на спиннере или показывает пустые экраны при первом открытии.
- Случайные ошибки фейкового API по умолчанию: рекрутер не должен их увидеть, если не включил специально.
- `any`, огромные компоненты по 500+ строк, расчёты прямо внутри JSX.
- Неверные финансовые расчёты (например, P/L, который не сходится с суммой по позициям).

## 4. Выбор подхода

Рассматривались три варианта:

| Вариант | Суть | Почему выбран / не выбран |
|---|---|---|
| **A. Vite + React + TS, лёгкий современный стек** | TanStack Query, Zustand, MSW, Tailwind + shadcn/ui | **Выбран.** Самый частый стек во frontend-вакансиях, компактный код, демо всегда работает, полный контроль над внешним видом. |
| B. Next.js (App Router) | SSR, route handlers как фейковый API | SSR почти ничего не даёт дашборду на моках и добавляет сложности. |
| C. React + Redux Toolkit + MUI/AntD | «Энтерпрайзный» стек | Готовые компоненты дают шаблонный вид, «терминальный» стиль на них собирать тяжелее. |

## 6. Предметная область

### 6.1 Сущности

```ts
type AssetClass = 'stock' | 'etf' | 'bond' | 'crypto';
// Облигации моделируются как облигационные фонды (цена за пай),
// чтобы все инструменты имели единую модель «количество × цена». [решение]

interface Asset {
  ticker: string;        // 'AAPL'
  name: string;          // 'Apple Inc.' (не переводится)
  class: AssetClass;
  sector: string | null; // ключ сектора для i18n: 'technology', 'healthcare'… (null для крипты и облигаций)
  quantityPrecision: number; // 4 для акций/ETF (дробные акции), 8 для крипты
}

interface Candle { date: string; open: number; high: number; low: number; close: number; volume: number }
// date — ISO 'YYYY-MM-DD', без времени и таймзон.

type TransactionType = 'buy' | 'sell' | 'dividend' | 'deposit' | 'withdrawal';

interface Transaction {
  id: string;
  date: string;          // 'YYYY-MM-DD'
  type: TransactionType;
  ticker: string | null; // null для deposit/withdrawal
  quantity: number | null; // только buy/sell
  price: number | null;    // только buy/sell, за единицу
  amount: number | null;   // только dividend/deposit/withdrawal — сумма в USD
  fee: number;           // ≥ 0, для buy/sell; для остальных 0
  note?: string;
}
```

Позиции, кэш, стоимость портфеля — **производные**. Они вычисляются из списка сделок и цен, а не хранятся.

### 6.2 Расчёты

Все расчёты — **чистые функции** в отдельном модуле, покрытые unit-тестами.

- **Кэш** = Σ deposits − Σ withdrawals − Σ(buy: qty×price + fee) + Σ(sell: qty×price − fee) + Σ dividends.
- **Позиция**: количество; **средняя цена покупки** по методу средней стоимости (average cost), комиссии включаются в стоимость покупки **[решение]**.
- **Продажа** уменьшает количество, средняя цена не меняется. **Реализованный P/L** = (цена продажи − средняя цена) × qty − комиссия.
- **Рыночная стоимость** = qty × текущая цена. **Нереализованный P/L** = рыночная стоимость − qty × средняя цена (в $ и %).
- **Изменение за день** = текущая цена против цены закрытия предыдущего дня (в $ и %) по активу и по портфелю.
- **Вес позиции** = рыночная стоимость / (сумма позиций + кэш).
- **История стоимости портфеля** по дням = кэш на дату + Σ qty на дату × close на дату.
- **Общая доходность** = (текущая стоимость − чистые вложения) / чистые вложения, где чистые вложения = deposits − withdrawals **[решение: простая доходность; TWR — вне объёма]**.
- **Аналитика**: месячная доходность (изменение стоимости за вычетом пополнений и выводов за месяц), максимальная просадка, годовая волатильность (σ дневных доходностей × √252), коэффициент Шарпа с фиксированной безрисковой ставкой 4% годовых (константа, указать в подсказке UI).
- Деньги округляются только при отображении. Внутри — обычные `number`, сравнение с допуском. Если удобнее, допустима целочисленная арифметика в центах: на усмотрение разработчика.

### 6.3 Демо-данные (генератор)

- **Детерминированный генератор с фиксированным seed**: одинаковые данные при каждом открытии, стабильные тесты и скриншоты.
- **~20 активов**: известные реальные тикеры для узнаваемости (AAPL, MSFT, NVDA, AMZN, JNJ, XOM, JPM…, ETF уровня VOO/QQQ, облигационные фонды уровня BND/TLT, BTC, ETH, SOL) **[решение]**. Цены вымышленные, но правдоподобного порядка. В интерфейсе постоянный бейдж «Демо-данные».
- **История цен**: дневные свечи примерно за 3 года, **заканчиваются на текущей реальной дате** (генерируются относительно `today`), чтобы демо всегда выглядело свежим. Модель — геометрическое броуновское движение с разной волатильностью по классам (крипта ≫ акции ≫ облигации), объёмы случайные.
- **Бенчмарк**: синтетический индекс «Benchmark» для сравнения на графике стоимости.
- **История сделок**: ~150 сделок за 3 года — начальное пополнение, регулярные пополнения, покупки, частичные продажи, дивиденды по части акций и ETF. Леджер обязан быть **консистентным**: кэш никогда не уходит в минус, нельзя продать больше, чем есть. Генератор проверяется тестом.
- Итоговый портфель — около $100–250k, в плюсе за весь период, но с заметными просадками, чтобы графики были интересными.

## 7. Фейковый API (MSW)

Обработчики MSW поверх in-memory «базы»: при старте база заполняется генератором, затем поверх применяются изменения пользователя из `localStorage`.

| Метод | URL | Описание |
|---|---|---|
| GET | `/api/assets` | список активов |
| GET | `/api/assets/:ticker/candles?range=1M\|3M\|6M\|YTD\|1Y\|ALL` | свечи |
| GET | `/api/portfolio/summary` | стоимость, кэш, изменение за день, общая доходность, P/L |
| GET | `/api/portfolio/history?range=…` | дневная стоимость портфеля и бенчмарка |
| GET | `/api/positions` | позиции с расчётами |
| GET | `/api/transactions?type=&ticker=&from=&to=&q=&sort=&page=&pageSize=` | серверная пагинация, фильтры, сортировка |
| POST | `/api/transactions` | создать (валидация на «сервере» тоже, ответ 422 с ошибками полей) |
| PUT | `/api/transactions/:id` | изменить |
| DELETE | `/api/transactions/:id` | удалить |
| GET | `/api/analytics` | месячные доходности, просадка, волатильность, Шарп, дивиденды по месяцам, распределение по секторам |
| POST | `/api/demo/reset` | сбросить пользовательские изменения |

- Задержка ответа 200–700 мс случайно.
- **Режим хаоса** выключен по умолчанию. Включается параметром `?chaos=1` или переключателем в настройках; тогда ~15% GET-запросов отвечают 500. Нужен, чтобы показать обработку ошибок (retry, error-состояния).
- Расчёты в обработчиках используют те же чистые функции из раздела 6.2 (один источник правды).
- Файл `mockServiceWorker.js` в `public/`. MSW включён и в production-сборке.
- Пользовательские изменения хранятся как «слой» поверх сгенерированных данных: добавленные сделки, изменённые и удалённые (по `id`). Сохраняются дата генерации и версия схемы. Сгенерированная история сдвигается вместе с текущей датой, поэтому при загрузке весь леджер перепроверяется. Если он стал некорректным или схема сменилась, пользовательский слой сбрасывается с тостом «Демо-данные обновлены» **[решение]**.

## 8. Live-цены

- Сервис `priceFeed` с интерфейсом, имитирующим WebSocket-подписку: `subscribe(tickers, onTick) → unsubscribe`.
- Каждые 2–4 секунды случайная часть активов получает тик: небольшое случайное изменение от последней цены. У крипты амплитуда больше.
- Тики меняют только **текущую цену** в клиентском состоянии (Zustand). История свечей не меняется. Портфельные показатели на экране (стоимость, P/L, изменение за день) пересчитываются от live-цен.
- При изменении цена в таблице и в карточках кратко **вспыхивает** зелёным или красным.
- Индикатор `● LIVE` в шапке с кнопкой паузы. Фид ставится на паузу, когда вкладка скрыта (`visibilitychange`).
- `prefers-reduced-motion`: без вспышек и анимаций, цены просто обновляются.
- Торговые часы не моделируются: тики идут всегда.

## 9. Страницы и интерфейс

### 9.1 Каркас (на всех страницах)
- **Боковая навигация** (сворачивается до иконок): Обзор, Позиции, Сделки, Аналитика.
- **Шапка**: стоимость портфеля и изменение за день (live), бейдж «Демо-данные», `● LIVE`/пауза, переключатель RU/EN, кнопка «Новая сделка».
- **Бегущая строка тикеров** под шапкой (тикер, цена, % за день, цвет). Останавливается при наведении.
- **Подвал/«О проекте»**: ссылки на GitHub, атрибуция TradingView, кнопка «Сбросить демо-данные».
- Горячие клавиши: `N` — новая сделка, `/` — фокус на поиск в текущей таблице, `?` — окно со списком клавиш **[решение: подходит стилю терминала, недорого]**.

### 9.2 Обзор `/`
- KPI-карточки: стоимость портфеля, изменение за день ($ и %), общая доходность, нереализованный P/L, кэш.
- Главный график стоимости портфеля (Lightweight Charts, area/line), периоды 1M / 3M / 6M / YTD / 1Y / ALL, переключатель «сравнить с бенчмарком».
- Donut: распределение по классам активов (с легендой и процентами).
- Лидеры роста и падения за день (по 3–5).
- Последние 5 сделок со ссылкой на все.

### 9.3 Позиции `/positions`
- Таблица (TanStack Table): тикер+название, класс, количество, средняя цена, текущая цена (live со вспышкой), изменение за день %, рыночная стоимость, P/L $ и %, вес %, спарклайн за 30 дней.
- Сортировка по любой колонке, поиск, фильтр по классу и сектору, итоговая строка.
- Клик по строке → страница актива.

### 9.4 Актив `/assets/:ticker`
- Шапка: тикер, название, класс, сектор, текущая цена (live), изменение.
- Свечной график с объёмами (Lightweight Charts), переключение «свечи/линия», периоды.
- Блок позиции: количество, средняя цена, стоимость, P/L, вес; если позиции нет — «Нет позиции».
- Сделки по этому активу.
- Кнопки «Купить» и «Продать» открывают форму сделки с подставленным тикером.
- Неизвестный тикер → понятная страница «Актив не найден».

### 9.5 Сделки `/transactions`
- Таблица с **серверной** пагинацией, сортировкой и фильтрами (тип, актив, диапазон дат) и поиском. Состояние фильтров синхронизировано с URL (можно поделиться ссылкой).
- Действия в строке: редактировать, удалить (с подтверждением).
- Экспорт текущей выборки в CSV.

### 9.6 Аналитика `/analytics`
- Тепловая карта месячной доходности (годы × месяцы).
- График просадки (drawdown).
- Метрики: волатильность, максимальная просадка, Шарп, у каждой подсказка с формулой простыми словами.
- Распределение по секторам (treemap или горизонтальные бары).
- Дивиденды по месяцам (столбчатая диаграмма).

### 9.7 Прочее
- 404-страница в стиле терминала.
- Error boundary на уровне страницы: сообщение и кнопка «Повторить».
- Для каждого блока: skeleton при загрузке, состояние ошибки с retry, пустое состояние (например, если пользователь удалил все сделки).

## 10. Форма сделки

Открывается как боковая панель (drawer) на десктопе и полноэкранно на мобильном. Используется для создания и редактирования.

**Поля зависят от типа:**

| Тип | Поля |
|---|---|
| Покупка / Продажа | актив (поиск-комбобокс), дата, количество, цена, комиссия, заметка |
| Дивиденд | актив, дата, сумма, заметка |
| Пополнение / Вывод | дата, сумма, заметка |

**Поведение**
- При выборе актива и даты цена подставляется из close на эту дату. Её можно изменить.
- Живой предпросмотр: итоговая сумма сделки, кэш после сделки, позиция после сделки.
- Сохранение с оптимистичным обновлением (TanStack Query) и откатом при ошибке. Тост «Сделка добавлена» / ошибка. После сохранения инвалидируются все зависимые запросы, и обновляется весь дашборд.

**Валидация (Zod на клиенте + та же проверка в обработчике MSW)**
- Дата не в будущем и не раньше начала истории цен актива.
- Количество > 0, с точностью не больше `quantityPrecision` актива. Цена > 0. Комиссия ≥ 0. Сумма > 0.
- Продажа: количество ≤ позиция на эту дату.
- Покупка и вывод: хватает кэша на эту дату.
- Дивиденд: на дату была позиция по активу.
- **Целостность леджера**: создание, изменение или удаление сделки не должно сделать некорректной любую *более позднюю* сделку (например, удаление покупки, после которой была продажа). Если делает — операция отклоняется с понятным объяснением, какая сделка ломается.
- Ошибки — у полей, на текущем языке.

## 11. Визуальный стиль: «терминал трейдера»

- Фон почти чёрный (не `#000`), панели чуть светлее, тонкие границы 1px, плотная сетка, минимум скруглений.
- Шрифты **[решение]**: моноширинный с табличными цифрами для всех чисел (например, JetBrains Mono или IBM Plex Mono), гротеск для текста (например, Inter). Подключение через Google Fonts или self-host.
- Акцентный цвет — один (например, янтарный или бирюзовый) для активных элементов. Зелёный и красный — только для роста и падения.
- Рост и падение передаются **не только цветом**: знак `+/−` и стрелка ▲▼.
- Цвета графиков задаются токенами (CSS-переменные), одна палитра для всех графиков, проверенная на контраст с тёмным фоном.
- Цвета и отступы — дизайн-токены в одном месте, а не магические значения в компонентах.
- Адаптивность: ≥1280 — полный макет; 768–1279 — свёрнутый сайдбар; <768 — нижняя навигация или бургер, KPI в 2 колонки, таблицы с горизонтальным скроллом и закреплённой первой колонкой.
- Доступность: навигация с клавиатуры, видимый фокус, контраст WCAG AA, `aria-label` и текстовое резюме у графиков, корректные роли у таблиц и диалогов.

## 12. i18n

- Языки: `ru`, `en`. По умолчанию — язык браузера (`ru*` → ru, иначе en). Выбор сохраняется в `localStorage`.
- Все строки интерфейса — в словарях. Захардкоженного текста в компонентах нет. Типизированные ключи (нет опечаток в ключах).
- Числа, валюта (USD), проценты, даты — через `Intl` по текущей локали: `$12,345.67` против `12 345,67 $`.
- Названия активов и тикеры не переводятся. Сектора, типы сделок, классы активов — переводятся.
- Атрибут `lang` у `<html>` меняется при переключении.

## 13. Архитектура и код

Рекомендуемая структура (допустимы разумные отклонения):

```
src/
  app/          # провайдеры, роутер, глобальные стили, layout
  pages/        # overview, positions, asset, transactions, analytics, not-found
  features/     # transaction-form, price-feed, locale-switch, demo-reset…
  entities/     # asset, transaction, position, portfolio: типы, api-хуки, UI-кусочки
  shared/
    api/        # http-клиент, query keys
    lib/        # финансовые расчёты (чистые функции), форматтеры, утилиты
    ui/         # shadcn-компоненты, базовые элементы, обёртки графиков
    i18n/       # конфиг и словари
    config/     # токены, константы
  mocks/        # генератор с seed, in-memory db, MSW-обработчики, persistence
```

- Компоненты небольшие. Логика — в хуках и чистых функциях.
- Query keys централизованы.
- Обёртки над Lightweight Charts — отдельные компоненты с корректной очисткой при размонтировании и ресайзом через `ResizeObserver`.
- Страницы грузятся лениво. Тяжёлые графические библиотеки — в отдельных чанках.
- Алиасы путей (`@/…`).

## 14. Тесты и CI

- **Unit (Vitest)**: все функции из 6.2 (средняя цена, реализованный и нереализованный P/L, кэш, история стоимости, доходности, просадка, волатильность, Шарп), валидация леджера, консистентность генератора, форматтеры для обеих локалей.
- **Компонентные (Testing Library)**: форма сделки (поля по типу, ошибки валидации, отправка), сортировка и фильтр таблицы позиций, переключение языка.
- **E2E (Playwright), смоук**: открыть обзор → данные видны → добавить покупку через форму → позиция и стоимость обновились → удалить сделку → вернулось; переключить язык; страница актива открывается.
- **GitHub Actions** на push и PR: lint, typecheck, unit, build, e2e.

## 16. Этапы реализации

Каждый этап заканчивается рабочей сборкой и коммитом.

3. **Каркас UI**: дизайн-токены и тема, layout (сайдбар, шапка, бегущая строка), i18n RU/EN, error boundaries, skeleton-ы.
4. **Обзор**.
5. **Позиции + страница актива**.
6. **Сделки + форма сделки** (создание, редактирование, удаление, валидация леджера, оптимистичные обновления, CSV).
7. **Аналитика**.
8. **Live-цены**: priceFeed, вспышки, пауза, reduced-motion.
9. **Полировка**: адаптив, доступность, горячие клавиши, пустые и ошибочные состояния, производительность.
10. **E2E, README, деплой.**
